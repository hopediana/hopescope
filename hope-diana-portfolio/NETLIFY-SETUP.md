# Publish the full portfolio on Netlify

This project now includes a **Netlify-compatible backend**. Your Moments stays inside the portfolio, with the same client legal-name/code login and admin workspace.

Netlify serves the site and runs the small API requests. **Supabase stores the private photographs, gallery metadata, and sessions.** Full-resolution uploads and downloads go directly to Supabase, avoiding Netlify Functions' request and response size limits.

The old Python server remains a local/self-hosted option. You do **not** run `python server.py setup` to set the password for the Netlify version.

## 1. Create and prepare Supabase

1. Create a Supabase project in your own account.
2. Open its **SQL Editor**.
3. Open `supabase/setup.sql` from this project, copy all of it into the editor, and run it.
4. Confirm there are four `hs_` tables in the public schema and a **private** storage bucket named `hopescope-private`.
5. In the project's API settings, find the project URL and a **server-side secret key** starting with `sb_secret_`. Use that secret key, not a public/publishable key. Keep it private.

The SQL enables row-level security without public/client read policies. Browser clients do not get the secret key. Netlify Functions check sessions before issuing short-lived file URLs. Do not make the bucket public or add broad public read/upload policies.

## 2. Import the project into Netlify

Use **Import from Git** with the project in your own repository. Netlify's configuration is supplied in `netlify.toml`.

| Setting | Value |
| --- | --- |
| Base directory | `hope-diana-portfolio` if that folder is inside the repository; otherwise leave blank when its contents are at the repository root |
| Build command | `npm run build` |
| Publish directory | `dist` |
| Functions directory | `netlify/functions` |
| Node version | `22` |

Do not use a raw HTML drag-and-drop upload for the full app. That does not run this project's build and deploy its API functions. If you prefer the Netlify CLI, link the project to your site and deploy with its build enabled.

The build copies an explicit list of public files into `dist`. It excludes local client uploads, database/configuration files, backend source, test credentials, and deployment documentation.

## 3. Set your private Netlify variables

In Netlify's project environment settings, add these values with **Functions scope** and **Production context**. Keep the password, session secret, and Supabase secret key marked secret where that option is available.

| Variable | What to enter |
| --- | --- |
| `SUPABASE_URL` | The Supabase project URL, such as `https://your-project.supabase.co` |
| `SUPABASE_SECRET_KEY` | The private server-side Supabase secret key beginning `sb_secret_` |
| `ADMIN_PASSWORD` | **Your admin password**, at least 12 characters |
| `SESSION_SECRET` | A separate random secret, at least 32 characters, generated by a password manager |
| `STORAGE_LIMIT_GB` | `100`, or your chosen original-photo allowance |
| `PUBLIC_URL` | Your exact canonical HTTPS website address, with no trailing path, e.g. `https://your-site.netlify.app` |

The adapter also retains compatibility with older `SUPABASE_SERVICE_ROLE_KEY` configurations, but use `SUPABASE_SECRET_KEY` for a new deployment.

There is no default admin password. Set it yourself in `ADMIN_PASSWORD`. Do not put any of these secrets into `script.js`, `moments_web/app.js`, HTML, or Git. `.env.example` contains placeholders only; real `.env` files are ignored by Git.

Keep production secrets out of untrusted deploy previews. To test a preview backend, use separate test credentials and a separate Supabase project. Use the exact `PUBLIC_URL` address when signing in. The production API rejects other deploy hostnames, preventing an old deploy URL from becoming another login endpoint. Update it and redeploy if you change the canonical domain.

## 4. Redeploy, then sign in

Redeploy after setting the variables so the functions load the new values.

1. Open your published portfolio.
2. Go to **Your Moments → Admin login**.
3. Enter the password from `ADMIN_PASSWORD`.
4. Select **New gallery**, enter the client's legal name and gallery details, and create it.
5. Copy the generated code before leaving or refreshing the admin page.
6. Upload finished photographs.
7. Share the portfolio URL and the client's name/code. The email option prepares a draft for you to review and send.

Clients choose **Your Moments → Client login** and enter their name and code. They can view and enlarge previews, download individual originals, or download selected/all photographs as ZIPs.

Until the variables and database are connected, the app explicitly reports that setup is incomplete. The standalone preview does not create real accounts or store client photos.

## 5. Test the published version before sending it to a client

If you have Node installed, run:

```bash
npm run check:deployment -- https://YOUR-SITE.netlify.app
```

Then test these steps in the actual published site:

- Sign in as admin and create a small test gallery.
- Upload two or three photos, including a file over 6 MB.
- Refresh/reopen the site and confirm the gallery is still there.
- In a private browser window, confirm a wrong name/code cannot open the gallery.
- Use the correct name/code, enlarge a preview, and download an original.
- Download a selection and the whole collection as ZIPs; open them and check the files.
- Replace the client code and confirm the old code/session no longer gets new file links.
- Test paused/expired access, then delete the test gallery.
- Redeploy once and confirm saved galleries are retained in Supabase.

These live checks cannot be completed until your own Netlify and Supabase settings are connected. No deployment, account changes, or purchases have been performed here.

## Storage capacity and limits

The configured allowance is **100 GB of original uploads**, not a purchased allocation. Choose a Supabase plan with enough real storage and transfer capacity for your work. Previews, metadata, temporary/pending uploads, and backups use additional space. Provider plan limits and usage charges are separate from this code setting.

- JPEG, PNG, or WebP, up to **50 MB** and **40 megapixels** per photo.
- Up to **500 photographs per gallery**; use another gallery for additional photos.
- The browser decodes each image and makes a smaller JPEG preview. The server checks file headers, actual stored sizes, MIME metadata, owner access, and the allowance before marking the upload ready.
- Originals keep their uploaded bytes and embedded metadata. Preview images are separately encoded.
- Pending/failed uploads are cancelled by the browser when possible; expired pending records and objects are cleaned during subsequent uploads. Check storage usage and backups periodically.
- Redeploying Netlify does not delete data stored in the connected Supabase project.

Backups are not automatic in this project. Use the backup/storage tools in your Supabase account and retain your own original photo exports.

## ZIP download behavior

ZIP files are built from the originals in the client's browser, so large galleries do not pass through Netlify Functions' response limits.

On browsers that allow saving directly to disk, the client chooses a ZIP filename and the app streams files into that archive. On browsers without that option, large collections are offered as smaller ZIP parts, up to roughly 150 MB of originals each, to bound memory use. The client downloads each part with its own button. Individual originals remain available in either case.

If a browser blocks the save picker, the smaller-ZIP flow is used. The browser may ask permission to save downloads. Do not close the page while a ZIP is being prepared.

## Access and password management

Admin and client sessions use HTTP-only cookies. Client codes are hashed and can only be displayed when first created or replaced. Rate limits are kept in the database so they also apply across separate function instances.

Change `ADMIN_PASSWORD` in Netlify and redeploy to change your admin password and invalidate previous admin sessions. Changing the client code invalidates that gallery's client sessions. Pause or expiry blocks new signed file URLs.

File URLs are temporary and remain usable for **up to 120 seconds** after they are issued, even if access is paused or the client signs out in that interval. Already downloaded or viewed files cannot be recalled. Do not share a signed file URL as the permanent gallery address.

This is a tested starter implementation, not an independently audited managed photo-delivery service. Its API tests use a simulated repository; real Supabase schema execution, storage, and Netlify deployment still require the live checks above.

## Existing local galleries

The Netlify backend uses Supabase, not the local Python SQLite database. Local client data is not automatically migrated. Keep the old data folder and your originals; recreate galleries and re-upload through the Netlify admin area, then issue the new codes. Do not upload the local `data/` directory to Netlify or commit it to Git.
